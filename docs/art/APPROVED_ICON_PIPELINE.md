# Approved icon promotion and live bindings

G4.1 separates source candidates, creator decisions and shipped resources. The source candidate library remains immutable and excluded by `.gdignore` and all three export presets. **Current count: 37 audited canonical candidates, zero creator approvals, zero promoted textures.** UI registry bindings are prepared; illustrated-item activation is blocked on exact creator decisions, not on a technical import shortcut.

## Promotion procedure

1. Review [the exact checklist](CLEAN_CUT_ICON_REVIEW.md). Obtain an explicit creator decision for each ID/version/hash or clearly enumerated batch. Record the conversation or issue reference and any conditions. Resolve conditions before promotion. Never infer approval from CI, a merge or a reference composition.
2. Add approved decisions to `docs/art/icon_approvals.json`, preserving schema version 1. A row requires `id`, `category` (`weapon`/`passive`), `artwork_version` (`v5-candidate`, or `clean-cut-v2` only for Touch Grass), `source_path`, `source_sha256`, `approval_status: CREATOR_APPROVED`, `approval_reference`, and `remaining_conditions: []`. This file is a reviewed record of creator decisions; the tool cannot grant approval. Do not insert hypothetical decisions to make tests pass.
3. Run `python3 scripts/promote_approved_icons.py --promote`. It checks canonical IDs/categories, the candidate manifest, the selected version and exact SHA before copying unchanged PNG bytes into `assets/runtime-icons/<weapons|passives>/<id>/<sha256>.png`. It writes a runtime manifest with source/promoted hashes, provenance, reference and intended usages. It refuses changed immutable destinations. Touch Grass v2 never inherits the older SVG. No SVG is loaded for runtime identity; reviewed PNGs avoid font substitution.
4. Run validation and inspect the actual live approved textures in all five requested layouts. Candidate source review is not live UI acceptance. Review readability, long names/effects, selected/focus/touch states, replacement and empty slots before claiming each approved asset integrated.
5. Export through the existing official build procedure. The pre-export validator rejects extra runtime files, stale unsigned import sidecars, hash changes, approval mismatches and missing platform exclusions. `scripts/check_icon_pack.py` parses the actual pinned Godot PCK format-4 directory, rejecting candidate/review entries and unsigned runtime textures, and requiring each promoted PNG's import mapping plus imported texture. It runs automatically after Web export. Confirm the exact deployed commit and inspect that downloaded pack too.

If approval is revoked, remove the runtime manifest entry and its copied resources in the same reviewed change. Validation deliberately fails if unregistered copied art remains. Preserve original candidates for provenance; do not delete them to hide approval gaps. Future approved source versions need an explicit scoped extension to the allowed-version map and manifest.

## Runtime behavior

`ApprovedIconRegistry` keys textures by category and existing stable ID, loads lazily once, and caches hits and misses. It rejects unsigned, duplicate and candidate-path mappings. Missing/unapproved/unknown items return null; validation emits an explicit pending-ID list. Production fallbacks retain the existing catalog glyph and actual item name instead of inventing similar art.

Normal, legendary and replacement cards share a passive TextureRect inside the existing icon well. Build slots and HUD request the same registry identity. Texture children ignore input so controls retain focus and touch ownership; rarity/selection remain in live UI styles. No gameplay catalog, RNG, profile, slot, timer or coefficient changes are introduced. All 28 passive IDs can be reviewed, but normal Alpha still exposes only its existing 23 passives.
